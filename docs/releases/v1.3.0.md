# howlinux 1.3.0 — draft release notes

Status: proposed next release; no v1.3.0 tag or release has been published.
The branch still reports version 1.2.0 until the release version is updated.

howlinux now renders its curated Markdown answers for the terminal and
expands the offline knowledge base from 39 to 110 entries.

## Readable terminal answers

- Headings, lists, quotes, emphasis, and links receive terminal formatting.
- Code fences and language markers such as ` ```bash ` are hidden. Shell
  examples remain literal and are indented for reading and copying.
- Interactive terminals receive automatic color. Redirected output,
  `TERM=dumb`, and a nonempty `NO_COLOR` use plain text.
- `--raw` displays the original Markdown body. JSON continues to include the
  original body in `content`; `--raw` and `--json` cannot be combined.

## 71 new knowledge entries

The additions include 51 command references and 20 practical guides covering:

- Shell quoting, variables, PATH, pipelines, redirection, scripts, and jobs.
- Text processing with tools such as `awk`, `sed`, `sort`, `cut`, and `xargs`.
- DNS, connectivity, listening ports, SSH keys, and remote file transfers.
- Memory and CPU diagnosis, filesystems, inodes, ownership, and permissions.
- Backups, synchronization, archives, and checksum verification.

Entries include examples, relevant caveats, upstream references, and links
to related guides. See the [complete catalog](../knowledge-catalog.md).

## Search improvements

Bounded rarity weighting prevents isolated rare words from gaining excessive
confidence as the catalog grows. Single-word aliases embedded in longer
queries no longer earn a phrase bonus, and command bonuses require a leading
command token. This avoids confusing ordinary words such as “file” with
explicit command requests. Existing log-following searches retain their
intended result.

## Compatibility

Human-readable answer output changes by default. Scripts that require the
original Markdown body should use `--raw` or extract `content` from JSON.
The renderer implements the documented authoring subset of Markdown, rather
than full CommonMark. The application remains offline and never executes
commands from an answer. No new runtime dependency is required.

## Validation

- Debug and Release builds and their complete test suites passed.
- 38 unit and application tests passed.
- Ranking checks passed for 231 positive queries and 15 negative queries.
- All 110 entries passed schema, reference, and authoring validation.
- All 126 Bash blocks passed syntax checks; 27 selected local example
  sequences were executed in temporary directories.
- Rendered, raw, and JSON output were checked across all 110 entries.
- Terminal color, `NO_COLOR`, installation, and package relocation were checked.

## Try the branch

```bash
howlinux show shell-quoting
howlinux "list listening ports"
howlinux "why is ram full"
howlinux --raw show rsync
```

These examples require a build or installation from
`feature/terminal-rendering-knowledge`; the existing v1.2.0 tag does not
include these changes.
